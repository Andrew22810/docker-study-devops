DockerFile
Директивы:
FROM задаёт родительский образ, на основе которого будет собираться новый образ
RUN выполняет указанные команды во время сборки
COPY копирует файлы и каталоги
ADD копирует файлы или каталоги из указанного источника и добавляет их в файловую систему
WORKDIR устанавливает рабочий каталог для всех последующих инструкций, все команды, которые идут после неё, будут выполняться относительно указанного каталога
ENV задаёт переменные окружения, которые становятся доступны во всех последующих инструкциях на этапе сборки образа и сохраняются в финальном образе 
ARG позволяет задать переменную, значение которой можно передать извне во время сборки образа
EXPOSE нужен для документирования портов, которые контейнер будет использовать для связи с другими контейнерами 
CMD задаёт команду и аргументы по умолчанию, которые будут выполнены при запуске контейнера из образа
USER определяет, от имени какого пользователя будут выполняться все последующие команды
ENTRYPOINT хз

Команды:
docker build запускает процесс создания пользовательского образа
docker images выводит список всех образов, которые находятся на локальном хосте
docker pull загружает готовый образ или репозиторий из удалённого реестра в локальную систему
docker push загружает локально собранный образ в удалённый реестр
docker tag создаёт тег для существующего образа
docker history показывает историю образа, из каких шагов он был собран и сколько места каждый шаг занимает
docker run нужен для создания и запуска нового контейнера на основе заданного образа
docker ps выводит список контейнеров, которые в данный момент активны
docker stop завершает работу запущенного контейнера
docker logs выводит логи указанного контейнера
docker exec хз
docker network хз

Тегирование: 
Полное имя образа в Docker состоит из нескольких частей:
Реестр указывает откуда брать образ. Если не указать, Docker по умолчанию использует Docker Hub (docker.io)
Пространство имён и репозиторий, определяют конкретный образ в реестре
Тег указывает версию или вариант образа

Контекст сборки:
Это набор файлов и каталогов, к которым Docker может получить доступ во время создания образа
Именно от него зависит, какие ресурсы будут использованы при сборке, и от его размера напрямую зависит скорость процесса
Какие файлы могут попасть в контекст: 
Контекст сборки формируется на основе аргумента, который передаётся команде docker build
Вот основные варианты: 
Локальная директория, например, . или /path/to/project.
Удаленный Git-репозиторий по URL и тд

Слои и кэширование:
Как писать Dockerfile для лёгкого образа, вот конкретные рекомендации:
1) Начинать надо с минимального образа, подходящего под стек
2) Надо минимизировать количество слоёв
3) Надо помещать инструкции, которые реже меняются
4) Надо использовать файл .dockerignore. Исключайте из контекста сборки ненужные файлы: логи, временные файлы, чтобы они не попадали в образ и тд

Docker compose:
Это инструмент для управления приложениями, которые состоят из нескольких взаимосвязанных контейнеров. Он позволяет описать всю инфраструктуру такого приложения в одном конфигурационном файле и запустить все компоненты одной командой
